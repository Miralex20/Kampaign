1. Project Objectives & Background

TeamManager includes a Digital Products marketplace where instructors and organizations can publish and sell video-based training courses.

Core Engineering Requirements:

  1. Low Latency & High Bandwidth Playback: Videos can be large (100MB+ per class). Streaming them directly through Django workers consumes server connections and leads to buffering.
  2. Smooth Scrubbing & Seeking: Users must be able to seek through 1080p/4K video with zero perceptible lag.
  3. Strict Access Control: Only students who have purchased the course or enrolled in a free product should be able to watch the classes.
  4. Sequential Viewing Enforcement: If an instructor enables sequential viewing, class $N$ cannot be viewed until class $N-1$ is completed.
  5. No S3 Egress Bills / Zero Disruptions: Existing direct S3 uploads for documents, invoices, PDFs, and avatars must not be broken or altered.

AWS CloudFront was selected as the Edge CDN layer to cache media at edge locations worldwide, using CloudFront Signed URLs for access control.

2. Initial Problem & Root Cause Diagnosis

The Original 302 Redirect Flow

Initially, the video player in CoursePlayerPage.jsx set the video source to Django's streaming view:

<video src="http://api.teammanager.com/api/digital-products/courses/4/classes/4/stream/?token=<JWT>" />

When the browser requested this URL, Django's ClassVideoStreamView:

  1. Authenticated the student via the JWT query parameter (QueryParamJWTAuthentication).
  2. Verified the student had purchased the course.
  3. Generated a CloudFront signed URL: https://d13xjfi0ctxoet.cloudfront.net/media/courses/video.mp4?Expires=...&Signature=...
  4. Returned an HTTP redirect:
    HTTP/1.1 302 Found
Location: https://d13xjfi0ctxoet.cloudfront.net/media/courses/video.mp4?Expires=...&Signature=...

3. The New Architecture: Asynchronous JSON Pre-Fetch

To eliminate cross-origin 302 redirects, we migrated to the industry-standard architecture used by major streaming platforms (e.g. YouTube, Vimeo):

  1. Asynchronous Signed URL Acquisition: The frontend makes an authenticated JSON call to /stream-url/.
  2. Direct Edge CDN Mount: The frontend receives the signed URL string and sets it directly as <video src="...">.
  3. Clean Edge Streaming: The browser requests byte ranges directly from AWS CloudFront edge PoPs. Zero redirects occur.

4. Step-by-Step AWS Setup

Here is the exact step-by-step procedure used to set up AWS CloudFront:

Step 4.1: Generating the RSA 2048-bit Key Pair

CloudFront requires an RSA 2048-bit key pair for URL signing.

# 1. Generate RSA private key
openssl genrsa -out cloudfront_private_key.pem 2048

# 2. Extract public key
openssl rsa -pubout -in cloudfront_private_key.pem -out cloudfront_public_key.pem

# 3. Base64-encode private key into a single line (ideal for container env vars)
base64 -w 0 cloudfront_private_key.pem > cloudfront_private_key.base64.txt

Step 4.2: Configuring CloudFront Public Key & Key Group

  1. In the AWS Management Console, navigate to CloudFront → Key management → Public keys.
  2. Click Create public key.
    • Name: teammanager-video-key
    • Key value: Pasted the full text of cloudfront_public_key.pem.
    • Clicked Create public key.
    • Recorded the Key ID: (e.g., K3ABC123EXAMPLE).
  3. Navigated to Key management → Key groups.
  4. Click Create key group.
    • Name: teammanager-video-key-group
    • Public keys: Selected teammanager-video-key.
    • Clicked Create key group.

Step 4.3: Creating the CloudFront Distribution

  1. Navigated to Distributions → Create distribution.
  2. Origin Settings:
    • Origin domain: Selected the existing S3 bucket (teammanager-media.s3.eu-west-1.amazonaws.com).
    • Origin path: Left blank.
    • Origin access: Kept standard/public access (since S3 policies were already established).
  3. Default Cache Behavior:
    • Viewer protocol policy: Redirect HTTP to HTTPS.
    • Allowed HTTP methods: GET, HEAD, OPTIONS.
    • Restrict viewer access: Yes.
    • Trusted authorization type: Trusted key groups.
    • Key group: Selected teammanager-video-key-group.
    • Cache policy: Selected Managed-CachingOptimized.

      Why Managed-CachingOptimized is critical: This policy natively passes and respects HTTP Range headers, enabling the CloudFront edge to cache byte chunks and serve HTTP 206 Partial Content responses without refetching the entire file from S3.

    • Origin request policy: Selected Managed-CORS-S3Origin.
    • Response headers policy: Selected Managed-CORS-and-SecurityHeadersPolicy.
  4. Clicked Create distribution.
  5. Once the distribution state changed to Enabled, recorded the domain name: d13xjfi0ctxoet.cloudfront.net.

Step 4.4: Why S3 Bucket Policies Remained Untouched

A major requirement was to avoid disturbing existing storage workflows:

  • Documents, invoices, images, and user avatars continue uploading directly to S3 via SafeS3Boto3Storage.
  • CloudFront simply reads from the bucket via AWS's internal network backbone.
  • No public bucket policies were opened or modified.

5.2: Cryptographic URL Signer (cloudfront_signer.py)

Created backend/digital_products/cloudfront_signer.py. Key features:

  • Uses cryptography and botocore.signers.CloudFrontSigner with RSA-SHA1 signing.
  • Flexible Private Key Loading: Loads from base64 string, PEM string, or disk path.
  • Handles media path prefixes cleanly (e.g. media/digital_products/courses/...).
  • Sets configurable expiration timestamps (default 2 hours).
def generate_signed_video_url(file_name_or_url: str, expires_in_seconds: int = None) -> str:
    domain = getattr(settings, 'CLOUDFRONT_DOMAIN', '').strip().rstrip('/')
    key_id = getattr(settings, 'CLOUDFRONT_KEY_ID', '').strip()
    if not domain or not key_id:
        raise ValueError("CLOUDFRONT_DOMAIN and CLOUDFRONT_KEY_ID must be configured.")

    if expires_in_seconds is None:
        expires_in_seconds = getattr(settings, 'CLOUDFRONT_URL_EXPIRATION_SECONDS', 7200)

    clean_path = file_name_or_url.lstrip('/')
    prefix = getattr(settings, 'CLOUDFRONT_MEDIA_PREFIX', 'media')
    if prefix:
        prefix = prefix.strip('/')
        if prefix and not clean_path.startswith(f"{prefix}/"):
            clean_path = f"{prefix}/{clean_path}"

    resource_url = f"https://{domain}/{clean_path}"
    signer = CloudFrontSigner(key_id, _rsa_signer)
    expire_time = timezone.now() + datetime.timedelta(seconds=expires_in_seconds)

    return signer.generate_presigned_url(resource_url, date_less_than=expire_time)

6. Frontend Video Player Walkthrough

In frontend/src/pages/modules/CoursePlayerPage.jsx:

6.1: Pre-Fetching Signed URLs on Active Class Change

// Stream URL cache mapped by class ID
const [streamUrls, setStreamUrls] = useState({})
const [loadingStreamUrl, setLoadingStreamUrl] = useState(false)

useEffect(() => {
  if (!courseId || !activeClassId || !activeClass?.stream_url) return
  if (streamUrls[activeClassId]) return // Already cached

  let cancelled = false
  setLoadingStreamUrl(true)

  api.get(`/api/digital-products/courses/${courseId}/classes/${activeClassId}/stream-url/`)
    .then((data) => {
      if (!cancelled && data?.url) {
        setStreamUrls((prev) => ({ ...prev, [activeClassId]: data.url }))
      }
    })
    .catch((err) => {
      console.warn('stream-url fetch failed, falling back to legacy redirect:', err)
    })
    .finally(() => {
      if (!cancelled) setLoadingStreamUrl(false)
    })

  return () => { cancelled = true }
}, [courseId, activeClassId, activeClass?.stream_url])

8. Production Deployment Blueprint

When deploying to production:

  1. Generate and Save Keys: Generate 2048-bit RSA keys using OpenSSL. Save CLOUDFRONT_PRIVATE_KEY_BASE64 in your secrets manager.
  2. AWS CloudFront Setup: Create Public Key, Key Group, and Distribution pointing to the production S3 bucket with Managed-CachingOptimized cache policy.
  3. Set Production Environment Variables:
    ENABLE_CLOUDFRONT_STREAMING=True
CLOUDFRONT_DOMAIN=<distribution-domain>.cloudfront.net
CLOUDFRONT_KEY_ID=<public-key-id>
CLOUDFRONT_PRIVATE_KEY_BASE64=<one-line-base64-string>
CLOUDFRONT_MEDIA_PREFIX=media
CLOUDFRONT_URL_EXPIRATION_SECONDS=7200
  4. Deploy Code & Restart: Deploy backend and frontend services.
  5. Rollback Plan: If needed, set ENABLE_CLOUDFRONT_STREAMING=False and restart workers to immediately fall back to direct S3 streaming.
